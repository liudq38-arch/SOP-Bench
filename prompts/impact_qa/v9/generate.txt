Write short first-person English procedural video QA in the style of EgoErrorVQA, from the supplied source annotation and a fallible visual note. The source is for writing reference answers, not input for a future evaluated model. Generate ONE main pair, and at most one second pair only if it contributes a clearly different operation detail.

Anomaly: ask about the specific action's correctness or the narrow error supported by its anomaly attributes. Prefer a focused question when wrong_tool or wrong_part is supplied. Otherwise ask if this particular action was performed correctly, explain only the known problem type, and connect it to the target action. Do not invent a physical mechanism. For example, wrong_part during placing supports a part-choice problem; it DOES NOT mean placing on the table was wrong or the part should have been inserted. Spatial alone does not identify a wrong destination; temporal alone does not mean early/late; handling alone does not establish force; procedural alone does not establish a skipped step. If the actual cause is unknown, do not ask for it and do not guess it.

Normal: ask a natural first-person confirmation about this exact action. A concise affirmative answer with the visible action is enough. Do not claim the whole task or assembly was correct. Recovery: ask what corrective action I performed, describe the action, and do not claim the earlier failure was fully repaired. No full SOP explanation is required.

Answers must read like direct answers to someone watching their own operation. Never use 'annotation', 'label', 'flagged', 'phase', 'classified', 'as indicated', 'normal disassembly', or 'recovery step' in questions or answers. Record source attribution in source_fields and evidence_basis, not in the answer. Avoid taxonomy dumps and generic yes/no alone when a concrete description is available.

For actual physical details use visual_note.question together with visual_note.answer. Prefer visible generic descriptions over tiny part specifications and tool-head types. The original action is a source label and can name the step; it is not proof that an insertion, loosening, extraction, or successful attachment visibly completed. Never invent direction, force, exact part size, a required replacement tool, target position, intended order, or prior failure. If a technical detail is absent, omit it. Use first-person 'I' in questions and answers.
