# v17：先备齐数据，再生成问题

本轮用户强调为出题模型提供足够数据。v16四角色流程已运行，但生成payload遗漏已有完整参考流程，未系统提供相邻动作、动作所在粗步骤和状态历史，部分端点也不能独立证明答案。继续增加审核次数不能替代补齐输入。v17以题型证据包作为生成入口。

## 每个事件的六部分输入

1. **问题目标与GT答案合同**：任务/型号/视角、目标动作或状态截止点、允许问什么、参考短答案、全部多标签异常属性、禁止推断、每项原记录及JSON pointer/hash。GT用于保证事实，不能当作视觉证据。
2. **公共参考流程**：完整五个粗步骤、官方手册来源、显示顺序图、每条边的权威级别。当前仅有手册显示顺序，不是完整强制拓扑；强制边列表为空，缺少来源时不生成“必须先A再B”“违反依赖”“应如何纠正”的题。挖掘自92视频的候选图不作为规范输入。
3. **当前执行上下文（仅生成/源审核可见）**：目标手的前后原子动作、重叠的粗步骤、邻近异常/恢复phase、相关组件状态变化和截止点状态。每段保留原始帧号及转换后的秒数，明确30fps，禁止把帧号当秒数。实际执行顺序与规范顺序分开存储。状态题的输入记录裁到截止点，不提供未来的状态值或后续动作内容。
4. **公共部件/动作参考**：可复用带TAS-S来源的其他训练执行示例，按名称排列；同一目标执行的示例禁用。现有示例是带动作标签的三帧图，不是人工组件分割或已验证的像素到部件图谱，不能称精确身份标注。参考图和公共流程必须同时提供给视觉盲答及最终评测，不能仅生成时看参考图。
5. **目标视觉与锚点**：现有抽帧复用，增加有目的的边界帧：工具取前/取后；顺序题两个动作起点前后；状态题最近状态变化前后与截止点；异常题异常前/中/后。每帧保存角色、时间、原图/裁剪、PTS、hash。状态截止题绝不使用截止之后的帧。图像总数最多32；用减少冗余均匀帧留出关键帧和参考图预算，不声称模型32图等于32帧足够覆盖任意视频。
6. **缺失项与出题资格**：精确物理错误机制/接收部件/强制依赖/规范时长没有来源时写null。先检查该题型要求的数据，再让模型观察证据是否可见。类别GT有而具体错误机制无，可以尝试类别题，不能扩展为原因/纠正题。

## 题型要求

|题型|必需GT/规范|必需视觉|缺少时|
|---|---|---|---|
|工具/动作|具名动作、手、区间|同一物体取前与离桌后；工具形状|补端点或换可同步视角；仍不清则hold|
|安装完成/状态|具名组件、截止点状态、状态定义；问接收部件时另需连接关系来源|组件可识别、连接部位与最终状态可见|缺身份/接口参考时不给“正确安装到某物”结论|
|实际顺序|两个动作的起始区间|两个动作都能识别且边界附近可见|补两个起点附近帧；不以流程文本代替观察|
|顺序正确性|带来源的适用依赖或明确比较对象|实际操作顺序|仅图示顺序时只能问与参考图是否相同，不能称错误|
|异常类别|TAS-B phase和完整属性|具体可见偏离或足够确认类别的操作证据|只有类别标签时隔离；不虚构错误机制|
|原因/纠正|明确偏离、规范与纠正依据/恢复动作|偏离及结果/恢复可见|当前数据常不足，禁用该题型直到补证|
|时长|已核验时间边界与端点语义|动作起止可辨识|仅可问观察/标注时长，不推断应该耗时|

## 生成逻辑

事件选择 → 题型资格/来源核验 → 检索上述证据包 → 盲视觉资格检查（无本次GT答案） → 若缺可取的关键帧，按缺失类型补一次证据 → 固定证据包版本 → 生成开放QA及MCQ → 无GT盲答、源审查、反驳审核、必要的证据子集验证 → 代码裁决 → 候选/隔离分流。

补证是增加信息，不改GT或提示“答案应该是什么”；补证前后均保存，最多两版，不重复请求直到模型迎合GT。每种补证请求为结构化need：boundary / identity_reference / wider_context / synchronized_view / normative_source。不能补到的规范/身份资料不交给模型补造。

## 首个实现范围

为230个已生成事件构建可追溯文本包、公共参考图、明确媒体计划和缺失项，先对原17混合样本实际补取锚点并核验。原v16及两批结果不覆盖。新包能证明“数据已供应/边界已覆盖”，不能自动证明“模型看懂/证据充分”；待盲视觉资格检查后才进入新一轮QA生成。正式发布门槛保持原记录。

## 已实现与实际验证

- 230事件证据包已构建，新增2653条上下文源引用；当前实际图像计划最多28张（上限32）。只对固定17混合事件实际补取并核验了视觉锚点；其余213是文本包＋取帧计划，不能称媒体全部已补齐。
- 原17样本的视觉资格检查：6可进入GT约束生成、8需补证、3结构/逻辑拒绝。3拒绝是自报可回答性/等级/needs不一致2及用参考图代替目标证据1。资格自报不是答案正确；扳手与部件顺序仍有自信误认。
- 6合资格进入完整GT＋视觉＋参考流程＋上下文生成、盲答、源审核和反驳审核：1模型候选、5隔离、0生成流程结构错误。安装与异常未在资格不足时强行生成。该1条与旧候选同事件，不计新增独立事件。
- 资格后生成仍必须重新盲答及核对GT，恰好拦住了资格阶段过度自信的案例；不能只用一个资格评分放行。此小样本未证明丰富输入提高了准确率；参考动作图并未解决所有组件身份歧义。
- `generation_payload`提供参考流程、GT合同、私有上下文与缺失项；`blind_payload`只提供问题、公共流程/示例与目标区间。生成、盲审和最终评测使用同一公共参考，参考图与目标帧ID分离。顺序题原子上下文仅检索两个起点前2秒/后3秒邻域，避免把整个长视频标签塞入prompt；完整流程作为另一字段保留。
- 运行代码：impact_qa/evidence_package.py；scripts/prepare_evidence_v17.py、qualify_evidence_v17.py、generate_evidence_v17.py。产物分别evidence_v17_inputs、evidence_v17_qualification、evidence_v17_generation。后续补证应优先解决已记录的组件身份、连接可见性、同步视角及规范缺口，不再以增加同模型投票替代数据。
