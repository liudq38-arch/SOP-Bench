# 提示词开发与版本记录

## v1：开发起点

四阶段提示：observe / ground / generate / review；文件 SHA-256 在 prompt_v1_manifest.json。开发集固定 20 事件，正式试制集尚未使用。

初步问题（未作为效果统计）：

- 首个观察把动作提示中的 M4 nut 写为视觉确定事实，图像本身不能可靠确认螺纹规格。后续版本需去除观察阶段的具体动作/对象提示，并限制把标注型号伪装成视觉事实。
- 首个事实汇总把所有可选 eligible_dimensions 原样列出，包括没有可用证据的时长与顺序；后续提示应明确这只是枚举候选，必须按事实选择子集。
- 单图服务冒烟将机械组件描述为 camera lens，说明接口成功不代表视觉语义正确。该返回只用于服务测试，不进入 QA 事实。

服务调整：eager 双并发经过文本/图片/视频冒烟，首次含算子编译开销；随后启用仅 decode 的 CUDA graph（1/2/4）及 max_num_seqs=4，保持模型与提示不变，复用已完成阶段缓存。变更发生在开发阶段，不混入试制冻结后的条件。

## v1 完整开发结果

固定 20 事件均完成，40 对候选。审核模型原始决定：pass 23、revise 7、reject 10；叠加可见性及证据结构检查后仅 14 对进入严格机器通过集合。6 个事件有视觉事实未引用观察的结构问题，1 个事件触发细化抽帧，3 个事件记录视觉/标注冲突。上述统计不是准确率。

具体失败：MA07LF04_Disassembly_A_001_ego__left__0110 把 recovery 标签改写成开放题；NA07GE21_Reassembly_A_001_ego__left__0049 将 M4 规格当作画面可见；多个 ground 输出在可用动作事实后附加没有 observation_ids 的总结事实。详见 development_v1_audit.md，保留所有候选及模型原文。

## v2 开发改动（尚未冻结）

观察不再接收动作/对象提示，保留任务、手及时间定位；限制推断规格，观察最多 5 项，事实最多 6 项。生成仅输出有视觉证据支持的操作问题，禁止元数据标签问答，允许不足两题。审核限制标签代替证据及规格、修复成功、规范顺序等推断。使用同一 20 事件，试制集未调用生成器。提示版本及哈希见 prompt_v2_manifest.json。

## v3 开发动机与协议变更

开发样本 SS07EL13_Disassembly_A_002_ego__right__0051 的原始目标区间为 72.922–83.638 s。抽帧拼图显示橙色工具接触部件出现在约 84 s 之后；v2 仍引用 84–86 s 上下文，生成目标段内使用橙色工具的答案，模型审核未发现时间边界问题。该检查为研究代理图像抽查，不记为人工审核。证据：dev_wrong_tool_contact.jpg、v2 对应原始记录。

因此第三轮同时更改输入采样与检查：overview 总数不超过 24，目标段至少 8、至多 16 帧，前后上下文各至多 4 帧；每帧显式 TARGET/CONTEXT_BEFORE/CONTEXT_AFTER。非顺序题引用段外帧会触发结构问题。细化仍至多 24 帧/1024 宽且仅目标内。观察和审核提示强调时间边界；unknowns 不能冒充缺少引用的视觉事实。第三轮与前两轮不是仅修改措辞的控制实验，应报告为流水线版本迭代。初始 10 事件采样预检另存 v3_sampling_precheck.json。

v2 完整结果：20/20 事件，无最终 API 错误，36 对候选；原始审核 pass=30/revise=2/reject=4，严格机器通过=22。5 个事件仍有结构问题，7 个记录视觉与标注冲突，0 个触发细化。不能只根据更高的自审通过比例宣称质量提升；上面的段外工具失败就是模型共同偏差的实例。

## v3 结果与直接目视复核

20/20 事件，38 对候选，无最终 API 错误；模型决定 pass=27/revise=3/reject=8，严格机器通过=13。10 个事件有证据引用/上下文问题。加入时间门槛改变了准入标准，所以不能直接将 13/38 与此前比例解释为质量升降。

用户要求继续直接检查和迭代。研究代理逐一对照 20 个开发事件的目标帧，详细结论在 visual_audit/agent_review.md。发现同模型自审存在明显共误：静止手掌被等同于无指尖运动、放到桌面被反写为插入、徒手分离被写为螺丝刀拆卸、问题偏离目标手、段后动作借用。正式试制未生成；不以模型 pass 比例作为冻结充分条件。

## v4：输入局部放大与精简提示

每目标段 12 个全帧（宽 896），加 4 个相同时刻的原始下部区域裁剪（宽 1024）；不把上下文帧混入初始视觉输入。裁剪区域固定归一化 x=0.05,y=0.25,w=0.9,h=0.75，不是人工手框，也可能漏掉靠上动作，故保留全帧。盲观察提示强调指尖接触和早期状态变化。文本生成阶段只接收可用视觉事实，不直接看到异常类型或动作标签；类别题仍由原标注构造。

四文件英文词数从 v3 的 1129 降至 v4 的 869（约减少 23%），仅为提示文本长度，不等同于总体 token/时延降幅。默认一题，第二题需不同维度；禁止 annotation_only 和 insufficient 凑数。观察先在 6 个难例试跑：00/01/05 的关键动作比 v3 更贴近目视内容，02/03 仍有泛化为静止支承的倾向，继续核对完整 QA，不能宣布问题全部解决。

服务在前三轮完成后扩为三个 TP2 实例：0/1、2/3、4/5，各并发 4，总并发 12。实际可见卡数仍为 7，未启动不存在的第八卡所需的第四服务。新增服务先完成多模态 API 冒烟，再用于开发验证。

## v4 小批检查及 v5 引用追溯修复

v4 只完成 6 个开发事件/7 对候选，没有扩展到全 20。检测到生成阶段删掉完整 observation 后，没有把 fact→observation→frame 映射同步传给生成器，模型自行配帧号。例如 F3 的观察证据在后部图，生成却填 focus_full_002。该问题不能靠“认真引用”的提示解决，归因为流水线接口缺少映射，见 v4_six_diagnostic.json。

v5 修复：只把来源有效的视觉事实交给生成器，并把事实绑定的帧显式补齐；最终 QA 的帧引用由代码按事实链导出，模型只选择事实 ID。源事实中无引用的 unknown/总结保留在诊断记录但不进入生成；与某条 QA 无关的源错误不再使其他有有效来源的题一起失效。增加指向不存在观察、错误帧映射、段外证据、来源隔离等测试（总计 5 项）。相同维度重复题及绝对静止措辞列入相应题目的保守质量门槛。

v5 保留 v4 的焦点证据采样和盲视觉观察；生成器新增动词 action_focus，仅用来挑选目标动作相关事实，不作为动作确实发生的证据，也不给生成器异常类型/phase/零件规格。保留完整源标注供事实对照、类别题及独立审核。复用已完成的相同观察缓存，在 3 服务/12 并发上跑完整 20 事件。

## v5 / v6 直接比较与输入协议核查

v5：20 事件/22 对候选，原始自审 pass=18/revise=1/reject=3，严格机器通过=16。v6：20 事件/22 对候选，pass=17/revise=2/reject=3，严格机器通过=12。直接目视检查仍发现明确语义错误；不能把 16/22 或 12/22 当作真实正确率。

针对用户询问实际输入，完成输入格式、时长、解码帧数、视觉 token 的实测报告 input_protocol.md。早期原生视频 probe 只在 processor 设置 16，长片实际仍送 32；该比较有帧数混杂，不能解释为纯输入模态优势。v6 显式在解码层固定 16，并禁止二次采样，10 事件均实际解出 16；另加 4 个原时刻局部图。v6 原生视频并未稳定优于 v5 多图，故没有仅因版本较新就宣布可大规模生成。

补充发现：工作台说明纸上有印刷部件图片，模型有时把指向图片解释为接触真实部件。v6 观察/审核提示明确区分平面图片与真实零件。

## v7 小对照

观察阶段只加入原人工标注动词 action_focus_hint，不提供具体对象规格或异常类型；这属于标注辅助定位，不再称盲视觉观察。独立审核只见目标范围、问题/答案与原生视频/裁剪，不见动作标签、异常标签或生成事实，以降低标签确认偏差。先在 8 个开发难例验证，再决定是否扩展完整开发集。试制集仍未用于调参。

研究代理另整理 20 条基于开发帧目视检查的修订建议，保存 outputs/impact_qa/agent_proposed_revisions.jsonl；它们独立于模型原候选，明确 creation_method，并全部 pending_human_review。不将代理写的修订计为真人标注或全自动生成成功。
