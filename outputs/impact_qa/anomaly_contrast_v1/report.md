# IMPACT 异常判据对照研究：Wrong tool / Spatial 第一轮

日期：2026-09-28。完成71个案例的原始视频采样帧直接复查：41个异常区间、30个正常匹配候选。共查看1420个帧条目，去重后1401个源帧。审查者为Codex，能看到GT；不是人类专家标注，也不是全视频逐帧审核。VLM观察阶段不接收GT类别、动作名或normal/anomaly角色。

本轮最有价值的结果是排除过宽的规则，并找到少数有上下文支持的工具更换解释。仍不能声称恢复了官方六类异常判定手册。原有QA没有重新生成或改写。

41个异常中17个短于1.5秒、4个有多类标签。短区间用于诊断标注边界，没有混入生产；所有共现类别保留。此前统计Spatial单标签有动作322区间中仅4个≥5秒，因此只看长段会遗漏主要标注形态。该分布不是短标注质量的保证。

## 2. 具体发现

### 2.1 Wrong tool可以有局部工具更换解释，但不能按工具名称判错

以下4例满足本轮较严格的局部序列解释条件：GT工具动作与可见工具跟踪一致，目标后更换工具并在同一局部组件继续操作。仍未看清具体螺丝槽型，不声称证明机械不适配或完成了纠错。

| 视频 | 目标源时间（秒） | 局部关系 | 阶段 |
|---|---|---|---|
| ER10WE06_Reassembly_B_005 | 93.833–108.333 | Phillips→Flat-head，后续对准/拧紧为normal | 发现 |
| NA07GE21_Disassembly_A_002 | 105.067–107.800 | Torx→Phillips，换工具阶段为recovery，后续松螺丝为normal | 发现 |
| LE06AS03_Disassembly_A_003 | 85.200–88.700 | Torx对准→Phillips对准/松螺丝为normal | 发现 |
| LE07UF17_Reassembly_A_002 | 283.733–293.767 | Phillips→Torx，收回Phillips为recovery，Torx后续操作为normal | 保留检验 |

注意同为型号A，既出现Torx→Phillips，也出现Phillips→Torx。不能写成“A型统一使用十字改锥”或者“拿Torx就是错”。必须关联具体操作和组件状态。以上是4个可复核的局部序列候选；其中两个不足5秒，只用于研究。

并非所有可见换工具都纳入这4例。例如AL07EJ17_Disassembly_B_005确实可见红黄工具换回蓝黑工具，但目标GT写tighten_screw，前后normal写loosen_screw；旋转方向未获视觉核准，因此作为动作语义疑点保留，没有加入严格候选。

检验5个Wrong tool中，仅1个清楚满足完整局部更换条件；1个虽然换工具，但中间连续使用同一工具的区间交替标为异常/normal，解释边界不清；1个只看到触及候选工具后转选其他工具，不能说已用错工具拧动；另2个缺少足够原因证据。这不是1/5分类准确率，而是冻结解释条件的材料覆盖情况。

反例：ER07AD15_Reassembly_A_004，25.733–26.300秒拿扳手为Wrong tool，紧接26.300–27.000秒同一次拿扳手标normal。LE07UF17_Disassembly_B_005也存在绿黑改锥连续对准中异常/normal交替。应保留边界疑点，不擅自改GT或将整个动作扩成异常。

### 2.2 用户提出的“拿着工具去放部件就是错误”不能直接作为通用规则

找到明确的normal对照：LE07UF17_Disassembly_A_004，右手160.733–162.667秒，GT动作place_screw，全段normal且六类异常全0。图像显示右手仍携红黄改锥伸入红盒，再携工具返回。微小螺丝释放受遮挡，但“持工具伸向料盒”本身不是充分异常条件。

[该例放大源帧](validation/direct_frames/ac_caf796a863e97b95/retained_tool_check.jpg)。原标注pointer和SHA、完整目标动作、源帧与时间均见[逐例审计](case_audit.jsonl)。该结果并不说明所有共同持有都正确，只说明不能用一条无条件规则解释所有案例。

### 2.3 Spatial不是单凭落点就能解释的类别

24个Spatial异常里，既有放工具、放微小螺母，也有拿弹簧、拿齿轮、持轴、搬工具、松螺丝收尾。部分GT动作名与短区间中最显眼的视觉动作粒度不同。例如loosen_screw异常区间中主要看到把改锥撤下放到垫面；不能直接将这个动作名当作原因。

检验例LE07UF17_Disassembly_A_001，287.233–290.667秒：左手把带圆形部分的轴组件移向红盒、再移向蓝盒，最终没有释放而带回。297.733–299.833秒normal则将较细裸轴放入蓝盒并释放。组件状态已不同，不能直接写“同一个裸轴先放错红盒、再正确放蓝盒”。

“离开黑色椭圆就错”“改锥临时放中央就错”“从一个盒转向另一个盒就是纠错”均缺少足够支持。12个保留Spatial例都没有补齐适用的摆放/朝向规范，因此本轮没有认证其具体规范性原因。可见落点和工具移位仍可以作为事实保存。

## 3. VLM观察流程的实际修正

先让模型看目标前4秒、后6秒的上下文视频，4fps，短目标8fps，26–124帧/请求。Smoke的2个输出出现跨区间帧引用，被校验拦截；随后把before/target/after的可引用帧分别写入schema，44个请求结构检查通过。

直接看源帧后发现：结构有效并不表示事实正确。模型会把后续红工具写进前面的绿工具目标、把放置说成继续转动、把左手取料归给右手。实际编码视频抽查未发现取错片段；其余媒体映射做了程序检查，没有宣称所有传入帧已人工验证。

第二轮将事实观察改为只传目标区间，收紧工作区裁剪，像素预算从8,388,608增至16,777,216，约24帧目标预算，动态1–8fps；实际6–24帧。目标句子限1–3句，观察最多3条。上下文另由源帧审查，不混进此调用。

8个定向困难例复测中，4个先前的主要物体/动作错误得到修正；2个仍有明显错误：扳手被识为绿工具、另一只手取料仍被写入目标手。另2个原本的大体动作就基本一致。这个样本不是随机集，也没有逐条认证所有接触与释放细节，不能报告为正式准确率提升；多项设置同时改变，不是因素消融。详见[8例对照记录](discovery/focus_comparison_notes.json)。

保留侧27个目标观察请求成功，但仍有把轴识别为工具、把触及工具说成丢入蓝盒、把放工具说成拿小件等错误。所有输出只作研究材料，未因模型自信或schema成功而自动放行。

## 4. 当前可以使用什么

1. MCQ类别答案继续按原生GT确定；明确目标手与时间，保留多标签。原因未知不能改成Correct，也不能因盲VLM未识别类别就否定GT。
2. 描述性开放QA可使用核验后的实际操作、工具更换、前后顺序；不要自动补“因为槽型不合适”“已经修好”等信息。
3. 异常原因字段单独保存：GT标签、观察事实、局部解释、规范来源、未知项。缺少规范或视觉证据时reason_status=unknown。仅有类别QA和带充分原因的QA应使用不同质量字段，避免把所有任务都要求成重新标注ATR。
4. 已准备[简短证据规则与few-shot](../../../prompts/impact_qa/anomaly_evidence_rules_v2.txt)，未接入正式生产。它约束事实和解释，并不伪装成官方六类定义。

本轮正式新增QA为0；确认的通用类别判据为0。4个局部序列候选值得后续做有限QA试制；不等于全量异常解释已经达标。
