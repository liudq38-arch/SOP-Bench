# 剩余五类异常逐类核验与六类工作判据

2026-09-28。结论：已按 Wrong tool → Wrong part → Handling → Procedural → Temporal 完成首轮直接源帧审查，并根据疑点做密集补查。结合此前 Spatial 专项，六类均有独立审查记录；这不意味着六类原始标注规则已被认证，也不是全量标注逐段审核。

## 覆盖与证据边界

本轮33个目标操作：28个原GT异常候选、5个normal比较候选；23次执行、13位参与者。每类目标数（包含normal）：Wrong tool 5、Wrong part 8、Handling 8、Procedural 6、Temporal 6。共72个视角窗口、1519帧条目、1512个唯一源帧；另查看3张局部连续帧放大图、12张完整源帧，均复用已有帧。审查者为Codex，GT可见，不是人类专家或独立盲测。没有分类accuracy或全数据误标率。

初始62窗口采用前4/目标10/后4帧；目标超过30秒时目标16帧。Wrong part/Procedural前后语境15/18秒，其余6/12秒。补查6个密集语境及2个不足1秒Handling事件的双视角；两个top目标分别连续26/28帧全部查看。ego按24.917 fps源PTS，front/top按30 fps；各视角候选对应并非帧级同步。短例为判据研究服务，不改变生产1.5秒过滤或≥5秒异常优先规则。

逐例事实、原标签、源SHA/JSON pointer、帧引用、局部解释及限制均在[visual_reviews.jsonl](visual_reviews.jsonl)，窗口级记录见[window_reviews.jsonl](window_reviews.jsonl)。六类工作判据见[rules.json](rules.json)。

## 1. Wrong tool：接口不适配，不能由“持着工具”触发

最可能判据：当前操作对象和目的确定后，实际施用工具的接口或能力不适合该操作；改变工具能够消除这个局部不适配。颜色只协助识别，批头/螺钉或型号适用关系才是关键。

- wt1，KI03AR28_Disassembly_B_005：57.467–60.533秒红黄改锥接触B端盖，之后换黑蓝改锥，后续端盖被拆下。wt1n是同次执行后续比较，不是独立正确性验证。
- wt2，NA07GE21_Disassembly_A_002：105.067–107.8秒绿黑改锥进入已打开的A壳体，随后红黄改锥在壳内操作。
- wt3，AL07EJ17_Disassembly_B_005：黑蓝→红黄→黑蓝，同一端盖局部继续操作。

以上三条支持局部工具不适配候选，置信度仅为未校准的中等；精确螺钉槽口有遮挡，不可推广至型号的每颗螺丝。wt4实际同时有手指和扳手，未确定谁在作用，不支持“徒手松螺母必然拿错工具”。[wt1源帧](frames/wt1_ego/sheet.jpg)。

## 2. Wrong part：先证实部件身份不适合，勿混淆试装/方向/顺序

工作定义是选用的部件、紧固件身份或规格不适合当前目标。操作了正确组件上的错误目标可以另记wrong_target候选，是否属于作者Wrong part尚不清楚，不能悄悄扩展定义。

七个原GT异常目标中，未得到足以确认“用了不相容部件”的样例：

- wp1与相邻normal wp1n一直是同一适配环。密集帧看清退出、翻转/转动及重套，属于方向/配合候选，未发生替换部件。[连续局部图](followups/wp1_dense_top_detail.jpg)。
- wp2从Box3拿轴承端盖反复贴合，是配合状态问题候选，身份并未明显错。
- wp3/wp4同一执行的front为Wrong part，top为Handling；实际调整轴/壳体，ego多在画外。类别差异不决定谁正确。
- wp5移开适配环后从同盒取小件；可能在排除遮挡，不能说已经装错部件。
- wp6用Torx处理待拆端盖，具体为何此时不能操作，需要独立前置约束。
- wp7的GT为pick_up_bearing_plate，但右手在Box4小件/环区域动作，Box3轴承端盖仍留原处，属于高优先级动作对象疑点。[原帧](frames/wp7_ego/f0000159.jpg)。

这是对7个定向异常目标的结果，不是全部42个Wrong part稳定区间。允许质疑标注，但未确认异常不能改为Correct。

## 3. Handling：释放/抓持控制失败有直接候选，双手协作不是错误

应检查物体是否脱手、工具是否实际滑脱、支撑是否失效、执行是否无法带动目标，而非把拿着工具、换握、徒手或转轴本身判错。

初看5个较长目标，主要是内部调整、转轴或双手协作。h3右手暂持Torx时左手正在拆取部件，未见妨碍；h2加密帧仍无法证明用力不当。这促使追加短事件，得到两个更有诊断价值的局部候选：

- h6，ER07AD15_Reassembly_A_003，top47.833–48.700秒：约48.0–48.3秒小件从手边离开、在台面运动，随后手指追取拿回。支持失去抓持控制候选；小件的M4规格来自GT，不能从像素独立确认。[26帧连续局部图](followups/h6_top_detail.jpg)。
- h7，KE03ER16_Disassembly_A_001，top19.400–20.333秒：松动后约19.8–20.2秒拨杆样组件及小件未被接住，离开壳体落到台面，随后放下改锥拾取。支持释放时未保持控制候选。[28帧连续局部图](followups/h7_top_detail.jpg)。

两例来自不同参与者/执行。意外性和“不允许直接落台”仍含任务约束判断，故不宣称普适Handling规则已经认证；未观察损坏、力矩或危险，不追加这些原因。

## 4. Procedural：用必要前置状态判定，不用唯一动作顺序判定

工作判据是必需前置条件未满足、必做步骤遗漏或当前状态下操作不成立。独立步骤可以换序；试配、为保管小件而回拧、主动纠正不自动错误。

pr1（SS07EL13_Reassembly_A_001）补齐完整链：早先放端盖；ego173–175秒再次打开；177–192秒在内侧长螺丝/螺母区域操作；195–198秒重新放端盖。支持“可能过早关闭、导致返工”的解释，但哪颗紧固件未完成、第一次是否只是试配尚未确认。可以出事实顺序题，暂不把因果写死。[前半](followups/frames/pr1_bridge1_ego/sheet.jpg)、[后半](followups/frames/pr1_bridge2_ego/sheet.jpg)。

pr4看清端盖已贴合而适配环仍在桌上，后来才套环；但后装环在画面中确实可尝试，不能从演示顺序推出其机械上不允许。pr2先松内部螺母、pr3拆卸中重新穿螺丝，均需排除合法替代流程。当前还没有已独立确认全部前置条件的正例。

## 5. Temporal：时长是测量结果，不是异常原因

应区分两个尚未统一的分支：违反明确时限/等待时机；没有任务进展且本可避免的停滞或冗余。后者必须检查双手和完整上下文，不能仅用“比别人慢”或重复次数。

- t1，87.8秒hold/null/transfer标签中持续有双手调整、轴壳分离/靠拢，不能描述为整段空等。
- t2，44.367秒反复调整扳手并松螺母，无法从用时断定无效。
- t3的14.7秒hold_lever实际包括取下、移向Box2和处理小件；另一次normal t3n为17.467秒，且也有活动。两者不是严格同状态对照，但不支持统一holding秒数阈值。
- t4视觉更像轴承端盖的贴合与紧固准备，GT却写mount_adapter_plate，动作对象应复核。
- t5反复调整齿轮/轴，可能存在困难，但无足够证据确定效率异常及其原因。

本轮未发现可靠的全类别秒数门槛，也未确认原作者Temporal是否包含普遍低效。生产“≥5秒优先”只是选样条件，绝不能写进异常定义。[t1图](frames/t1_ego/sheet.jpg)、[t3比较图](frames/t3n_ego/sheet.jpg)。

## 六类边界与QA使用方式

Spatial沿用[此前专项证据](../spatial_rules_v1/report.md)：已知指定盒位时的错误归位有支持；随手暂放、持工具入盒、调整姿态不自动异常。

最小改动帮助区分类别：换工具才解决→Wrong tool；换部件身份才解决→Wrong part；保持身份、改位置/方向→Spatial候选；保持接口/目标、改抓持与控制→Handling；先补必要状态→Procedural；在其他条件有效时改变开始/等待/持续时间→Temporal。它是解释维度，不是互斥分类器；每类分别有证据才可并存。

QA应分开保存原GT答案、独立审核结论和可见事实。GT疑似错标或事件对应错误者暂不进入确定原因题；可靠事件描述、部件状态、观察顺序仍可生成。Correct必须有适用范围和足够可见性，unknown不得映射Correct。单选题需要该目标内只有一个已核实类型；多异常/多标签保留时间与对象，不为凑单选而删标签。参考[prompt v5](../../../prompts/impact_qa/anomaly_first_principles_v5.txt)尚未接入生产，不宣称已改善模型指标。
